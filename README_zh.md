# 变形乘波体的认证滚动策略迭代

[English](README.md)

[MATLAB 构型生成与气动数据库源码](upstream_matlab/README.md)：上游原始代码、参考输入、入口说明及 SHA-256 清单。

本仓库包含在固定 1200 s 滑翔任务中学习变形高超声速乘波体升力系数调度的代码与输入数据。每一个实际执行的控制步都必须先通过安全认证链。策略通过基于滚动仿真（rollout）的近似策略迭代改进：在确定性的认证仿真中分支，精确测量动作优势；用神经网络集成对其泛化；只有认证后的回报提高时才接受新策略。

## 问题

* **对象。** 球形地球上的三自由度质点飞行（状态：高度 h、速度 V、航迹角 gamma、航程 s），控制量为攻角 alpha 与变形构型；构型在 298 个预计算外形之间过渡（每次 8 s）。气动系数由预计算数据库按马赫数与攻角插值。
* **任务。** 从固定初始状态飞行 1200 s，目标为 1200 s 时的航程。回报 G = s(1200 s) / 2400 km + 0.10（任务成功时：无约束违反、终端高度 >= 20 km、速度 >= 800 m/s、航程 >= 360 km）。
* **约束。** 高度 20–80 km，|gamma| <= 0.35 rad，攻角 -2°–12° 且变化率 <= 5°/s，动压 <= 80 kPa，过载 <= 3 g，热流代理 <= 2 MW/m²。
* **动作。** 每 12 s 从 19 个绝对升力系数目标中选择一个（-0.01, 0, 0.01, 0.015, …, 0.06, 0.07, …, 0.12），在随后 4 个 3 s 控制步内保持。

## 认证执行

一个 3 s 控制步只有在针对该精确状态与动作的证书通过后才执行。对给定的升力目标，认证链用两阶段最优控制问题的代理模型计算攻角与构型指令（代理模型超出训练域时改用精确物理基线，最后的兜底为完整求解最优控制问题），在约束下修正指令，检查 30 s 前瞻内是否存在可恢复的后续飞行，并独立积分动力学（审计步长 0.1 s）以确认所有约束。若所请求的动作无法认证，则执行可认证的最接近动作；若没有任何动作可认证，飞行以失败结束。下文所有学习信号都只来自这样的认证飞行。

## 方法

策略迭代从恒定策略 CL = 0.04（pi_0）开始。第 k 次迭代，当前策略为 pi_k：

1. **精确优势标签。** 在 25 个决策时刻（间隔 48 s，起点每次迭代平移 12 s）复制仿真，令两个备选动作保持一个决策周期：pi(s) ± 1 档或 ± 2 档，在任务的相邻 96 s 区段之间以及相邻两轮遍历之间交替，因此两轮遍历即可覆盖每个状态的全部 4 个相邻动作；随后按 pi_k 名义决策序列**开环重放**飞至任务结束。由于仿真是确定性的，标签 A(s, a) = G_rest(a) − G_rest(pi(s)) 是精确的；不改变动作的分支就是名义轨迹本身。
2. **优势网络集成。** 5 个网络（4 个输入，4 个各 64 单元的 tanh 隐藏层，19 个输出）在标签状态的自助采样上拟合，目标值下截断，并用袋外样本提前停止。输入为飞行状态与时间（h, V, gamma, t）；使用最近 7 个策略版本的标签，权重为 0.5^版本龄。在训练运行的标签存档上，4 个隐藏层的网络预测下一次迭代优势的能力优于两层网络（秩相关 0.65，16-16 为 0.53）；加宽两层网络没有改善，超过 4 层也没有进一步改善。`--hidden` 设置各层宽度。
3. **候选策略。** 在 pi_k 后追加一个网络阶段：在当前动作 ±2 档内选择置信下界（均值 − 标准差）最大的动作，仅当该下界超过阈值（0.25e-4 至 1.5e-4 之间 6 个阈值）且决策时刻距有标签的时刻不超过 48 s 时才替换。
4. **单调接受。** 每个候选策略都经认证完整飞行一次；只有最优候选的精确回报高于 G(pi_k) 时才被接受，否则继续积累标签。

停止规则：连续两轮遍历全部状态起点均无正优势、无无效分支且无接受，或连续三轮遍历无接受。

**对照（消融）设置。** 方法的前一版本以**闭环**方式续飞分支（备选动作之后由 pi 重新决策），使用包括策略自身动作反馈（攻角与上一升力目标）在内的全部 6 个特征，并额外由正优势标签构造精确覆盖候选。对应参数为 `--continuation closed-loop --inputs all --overrides --hidden 16,16`，各开关可单独使用（单独使用 `--hidden 16,16` 即为两层网络版本的方法）。

## 数据

`configs/`、`data/` 中的每个文件以及 `morphing_waverider` 包都列在 `data/SHA256SUMS` 中；每次飞行先校验它们，任何文件被改动都会停止。下表标明飞行中代码实际加载哪些文件；其余文件记录这些输入的来源。

**配置（`configs/`）**

| 文件 | 内容 | 飞行中使用 |
|---|---|---|
| `mission.yaml` | 1200 s 任务、3 s 控制步、初始状态、路径约束、终端门限、回报定义；其他配置文件的路径 | 是 |
| `environment.yaml` | 大气模型、球形地球、终端高度、所需航程（与 `mission.yaml` 交叉校验） | 是 |
| `vehicle.yaml` | 质量、路径约束、热流代理、攻角变化率限制。其中 `synthetic_aero_dataset` 一节属于原质点动力学包，不被使用 | 是 |
| `teacher_profile.json` | 气动表的参考质量与参考面积；必须与 `mission.yaml`、`vehicle.yaml` 一致 | 是（一致性校验） |
| `trajectory.yaml` | 最优控制问题的时域（60 s）、区间与积分步数 | 是 |
| `runtime.json` | 认证链：代理模型、兜底方案、约束修正器、30 s 前瞻、19 个 CL 动作、8 s 构型过渡、OCP 设置 | 是 |

**候选构型的气动数据（`data/geometry_subset/`）**

飞行中每个构型使用一张气动表：18 个马赫数（3.5–8.25）× 20 个攻角（−1°–12°）上的升力、压差阻力与俯仰力矩系数，由条带激波-膨胀波模型计算（仅压差阻力，不含摩擦）。对一个升力目标，代码在每个构型自己的表内插值（先马赫数方向 PCHIP，再攻角方向 PCHIP），求出达到目标所需的攻角，并选择该处阻力最小的构型。在 8 s 构型过渡期间，旧构型与新构型的系数在同一马赫数与攻角下线性混合。

| 文件 | 内容 | 飞行中使用 |
|---|---|---|
| `aerodynamics/p2_grid.npz` | 上述气动表，数组维度为 [构型, 马赫数, 攻角]，附有效性掩码与构型参数 | **是，飞行唯一使用的气动数据** |
| `manifest.json` | 构型编号、数组形状、每个文件的 SHA-256；其哈希把代理模型与该数据快照绑定 | 是 |
| `aerodynamics/p2_common_grid.csv` | 同一气动表的 CSV 版本，包括无效点及原因 | 否 |
| `aerodynamics/equal_lift.csv` | 每个构型在 108 个工况（18 个马赫数 × 6 个升力目标）下的阻力 | 否 |
| `action_index.csv`、`candidate_inventory.csv` | 编号与构型 ID 的对应；外形参数、相对 G42 的体积比与厚度比、几何验证记录 | 否 |
| `geometries/<id>/native_geometry.mat` | 298 个构型各自的外形（G42 是每次飞行的初始构型） | 否 |
| `benchmarks/` | 每个工况的最优构型、每个固定构型在 108 个工况上的平均阻力 | 否 |
| `metadata/`、`provenance/` | 网格、参考面积与长度、模型设置；气动计算的脚本与源数据哈希 | 否 |
| `figures/` | 各马赫数与升力目标下压差阻力最小的构型 | 否 |

## 安装

需要 Python 3.11。

```bash
python -m pip install -r requirements.txt
python -m pytest -q
```

C 编译器为可选项（PATH 中的 `gcc`，或环境变量 `CERTIFIED_FLIGHT_CC` 指定的路径）：若可用，CasADi 函数会一次性编译到 `.cache/` 以加快速度；否则由 CasADi 虚拟机计算同一表达式图，结果相同。

## 使用

按所提方法训练（每个工作进程一个进程；一次迭代约执行 1.7 万个 3 s 认证步）：

```bash
python scripts/train.py --out runs/seed17 --seed 17 --workers 14
```

运行目录包含 `state.json`（策略、标签、各次迭代记录），以及每次迭代一个文件夹（标签与被接受候选策略的证书）。中断后重复同一命令即可续跑。对照设置：

```bash
python scripts/train.py --out runs/baseline_seed17 --seed 17 --continuation closed-loop --inputs all --overrides --hidden 16,16
```

多个随机种子：`SEEDS="17 23 41" bash scripts/run_seeds.sh`。

## 评估

训练后的策略从扰动初始状态出发飞行，并与从相同状态出发的恒定策略 CL = 0.025 比较；此外，在其名义飞行中将某一次决策改变一档，之后分别闭环续飞（策略重新决策）与开环续飞（重放名义决策）。定义了三个测试集，各含 12 s 决策网格上的 7 个扰动时刻：

* **held-out-2**（默认）：所提方法的测试集。由固定种子 20261023（初始状态与扰动时刻各用独立随机数流）在 |dh| <= 2000 m、|dV| <= 100 m/s 内均匀抽取 40 个初始状态偏移，与其他测试集不重叠。它在所提方法训练之前即已固定。
* **held-out-1**：以同样方式由其他随机数流生成，曾用于测试两层网络（16-16）版本的方法。改变网络规模时其结果已知，因此不是所提方法的干净测试。
* **开发集**：名义状态、网格上的 12 个扰动状态与 7 个扰动时刻。这些测试曾用于诊断前一版方法和选择最终方法，因此其结果偏向所选方法，不能作为泛化能力的度量。

独立测试集的初始状态均未用于训练或开发。其扰动时刻此前从未在评估中使用，但扰动发生在名义轨迹上，而名义轨迹上的决策状态在训练中会被分支；因此扰动测试衡量的是策略对扰动的反应，而非在未见状态上的性能。

```bash
python scripts/evaluate.py runs/seed17/state.json --out evaluation/seed17 --reference-out evaluation/reference
python scripts/evaluate.py runs/seed23/state.json --out evaluation/seed23 --reference-out evaluation/reference
python scripts/compare.py --out evaluation/comparison.json seed17=evaluation/seed17 seed23=evaluation/seed23
```

`--reference-out` 使多个策略共享基准飞行。`compare.py` 对每个策略报告相对基准的平均增益及配对自助法 95% 置信区间、胜出次数与最差情况（另外也只统计基准完成任务的初始状态，因为失败的基准飞行按截断航程计入），以及第一个策略与其余各策略的配对差异。`--test-set held-out-1` 或 `--test-set development` 选择其他测试集。

## 可复现性

飞行与网络拟合都是确定性的：所有随机数都有固定种子，BLAS 单线程运行，因此在相同平台与库版本下可逐位复现。不同 CPU 可能改变浮点结果的末位：飞行 240 s 后，两台机器的状态差异相对于各分量的典型量级约为 1e-14（航程差 5 nm）。在整个训练过程中，这类差异可能改变某个离散决策，因此不同机器上的训练结果不一定完全相同。两个包在导入时设置 BLAS 线程环境变量；在自己的脚本中调用时，应先导入它们再导入 numpy（`scripts/` 即如此）。

每次飞行前都会按 `data/SHA256SUMS` 校验配置文件、输入数据与物理库，任何文件被修改都会停止运行。
