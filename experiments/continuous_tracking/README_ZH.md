# 连续迎角、CL跟踪优先的独立实验

协议 `continuous-alpha-full-horizon-tracking/1`。不加载旧代理、旧策略、Replay或网络检查点，不改变原训练入口和原配置。

## 改动的研究定义

- 使用原298构型库、Generator等CL最小压力阻力规则、8秒线性变构、19档绝对CL和原平动3DOF右端项。
- 迎角由“0.5秒分段常数、节点差分限速”改为连续分段线性轨迹。当前实际迎角是首节点，斜率受原5°/s限值约束。这是理想限速内环，不是经辨识的俯仰/执行器动力学。
- Pre与Final都使用真实60秒OCP，每3秒执行一次，末段按剩余时间截断。Pre输出仍由实际预测状态计算飞行Mach，Generator没有使用设计Mach代替。
- CL跟踪使用全规划时域RK4逐时刻平方误差积分，按3秒归一化。预测未来CL保持当前请求；这是假设，不是已知的未来策略。
- 每个OCP按词典序近似分两次求解：首先在完整规划安全约束下最小化当前要执行的3秒逐时刻CL误差，再在该误差的1%相对余量加1e-6绝对余量以内优化全时域跟踪和原经济目标。第一阶段求得的是局部可行最优候选，不宣称全局最优。未来参考仍计入目标，但不能为了未来误差更小而牺牲当前已下达的指令。原阻力、热、航程、终端项权重保留，目标优先级已经改变。
- 平滑项包括从实际迎角到首个终点的变化，按0.5秒参考间隔归一化为迎角变化率平方积分，消除周期入口的免费跳变。
- 规划内部RK4步长上限0.5秒。内部归一化约束余量1e-4用于避免贴边计划因独立积分差异越界；没有放宽任何原物理限值。最早的无余量诊断已单独保存。
- 首选上一Final移位的迎角初值，按当前状态/新构型重新积分；不复用旧状态初值或乘子。热启动未通过求解或独立审计时，仅再试一次原冷初值，记录全部尝试。
- 可将CasADi生成的目标、约束和精确导数编译为本机库，缓存于`.cache/continuous_nlp`。采用`-O0 -fno-fast-math -ffp-contract=off`，不使用近似导数；测试逐位比较解释执行和编译后的目标、约束、梯度和雅可比矩阵。60秒以下的末段使用原图解释执行，避免为每个末段网格重复编译。

## 安全证据与质量证据

Pre、Final全规划及当前执行3秒分别通过0.1秒/0.5秒RK4独立审计，检查每个RK阶段的原物理约束。执行前严格核对当前区间终点与全计划已审计前缀相同。

这是新连续控制协议的真实OCP安全见证，不复用原代理P1或原离散迎角H30资格报告，不声称已取得旧认证协议的等价资格。失败时保存状态，禁止提交未经审计的动作。

CL质量阈值只用于诊断：绝对均值误差0.0025、RMSE 0.005、峰值误差0.01。它们是显式实验标准，不是新的物理限制。物理安全而质量不合格时记录 `SAFE_WITH_TRACKING_DEVIATION`，不能把它说成跟踪成功，也不证明偏离是安全所必需。继承旧轨迹的高迎角初态时，连续跟踪存在不可消除的初始瞬态。

## 运行

在仓库根目录、已有Python环境中：

```powershell
python scripts/check_continuous_tracking.py --trajectory <保存的fig_traj.json> --times 0 24 150 300 600 603 900 1197 --out runs/tracking_frozen
python scripts/evaluate_continuous_tracking.py --cl 0.025 --max-decisions 400 --out runs/tracking_full
python -m pytest -p no:cacheprovider
```

输出目录必须不存在。每步保存两个完整OCP计划、求解日志、双网格轨迹、当前区间审计、配置/源码/输入哈希，以及最新 `result.json`。失败保存 `stop_state.json`；`checkpoint.json`是诊断状态快照，目前不提供续跑入口，不能冒充可精确恢复训练的checkpoint。

冻结状态对照从相同平动状态、上一迎角、构型/变构进度、CL请求开始；由于迎角执行模型显式改变，它不是旧模型下逐位一致的对照。完整飞行必须真实滚动执行，不能用冻结状态结果推断1200秒成功或航程收益。
